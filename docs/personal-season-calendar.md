# 개인 시즌방 달력과 오픈 안내

- 크루 달력은 날짜를 선택해도 월 전체를 유지한다. 선택한 날짜의 현황만 바꾼다. 임원진·게스트·강습 태그와 24px 기본 프로필을 사용한다.
- 집계가 없는 날짜는 빈칸으로 두고 ‘현황 없음’ 범례는 표시하지 않는다. 집계 부재를 여유/예약 가능으로 간주하지 않는다.
- `bookable`, `opensAt`, `unavailableReason`은 서버가 현재 크루 정책과 한국 시간을 기준으로 계산한다. 서버는 신청 시 다시 검사한다. UI는 오픈 전 버튼을 비활성화하고 오픈 시각을 안내한다. 새로고침으로 최신 판정을 다시 가져올 수 있다.
- 관리자는 주간 오픈 요일·시각, 숙박 시작 오프셋, 오픈할 숙박 일수, 상시 오픈을 저장한다. 새 `reservationWindowDays`는 정확한 일수, 0은 무제한이다. null인 기존 크루는 기존 범위 규칙을 보존한다.
- 나의 달력은 YYYY-MM-DD 문자열로 날짜를 비교하고 confirmed/waiting 상태를 명시적으로 구분한다. 실패한 조회를 빈 예약으로 표시하지 않는다. 저장 중 중복 요청과 오래된 월 조회 응답을 막는다.
- 강습은 크루가 활성화하고 본인의 확정 예약인 경우 신청할 수 있다. 이미 신청한 강습은 크루가 설정을 끈 뒤에도 취소할 수 있다.
- 홈은 기존 회색 프레임·흰 카드 계열의 작은 ‘나의 달력’을 제공한다. 이번 주·다음 주 14일에 필요한 월만 최대 두 번 조회한다. 상태는 색상 아이콘과 확정/대기 문구로 안내한다. 상단 본문 간격을 확보한다.
- B 버디는 빈 개인 예약 안내와 처리 대기 안내에 작은 보조 이미지로 사용한다. 예약 정보·필수 입력·프로필을 대체하지 않는다. 생성/편집 프롬프트는 design/buddy-variations.md에 기록한다.

검증: 전체 Vitest/타입/ESLint/빌드/번들/API 계약, 월말 14일 조회, 개인 상태·강습 유지·실패 상태, Chromium 320/390/768/1440과 WebKit 390의 예약/관리/개인 달력/홈/오픈 전 차단. backend 먼저 배포해야 한다. 실제 스테이징 검증은 관리자 병합 후 진행한다.
