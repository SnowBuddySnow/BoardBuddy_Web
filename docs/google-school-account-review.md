# 학교 Google 계정 연동 검토

검토일: 2026-11-16. 이 문서는 제안이며, 실제 Google 로그인 연결은 아직 구현하지 않았다.
홈·마이페이지·가입 2단계 및 입력 직후 학교 이메일 인증은 이번 변경에 구현했다.

## 추천 방향

학교별 계정 체계가 달라 **현재는 카카오 로그인과 학교 이메일 인증을 기본 경로로 유지**한다.
Google 연동은 지원 학교를 확인한 후 추가할 선택 경로로 제안한다.
학교가 Google Workspace를 사용하는 경우 학교 Google 계정으로 가입하면서 학교 계정까지
확인할 수 있다. 신규 학생에게 카카오 로그인 후 Google 로그인까지
연속으로 요구하면 오히려 단계가 늘어난다. 기존 카카오 회원은 계정 관리에서 학교 Google
계정을 연결하고, 새 계정을 만들지 않도록 한다. Google을 사용하지 않거나 학교 정책으로
연동이 차단되는 경우에는 현재 학교 이메일 인증번호 경로를 유지한다.

추천 흐름:

1. 초대/시즌방 신청 링크 → 공개 현황 확인 → 신청할 때 가입.
2. 학교 선택 → `학교 Google 계정으로 계속하기` 또는 `카카오로 계속하기`.
3. Google 경로는 선택 학교와 일치하는 관리형 계정인지 서버에서 확인하고 학교 인증을 완료.
4. 이름 확인·학번·필요한 성별·휴대폰 인증 등 부족한 항목만 입력.
5. 약관·가입 → 원래 신청 화면 복귀. 크루 가입 승인과 운영 권한은 기존 정책을 유지.

학교 계정 소유 확인은 현재 재학 상태나 동아리 부원 자격을 자동 증명하지 않는다.

## 가져올 수 있는 정보와 한계

| 정보 | 일반적인 Google 로그인 | 권장 처리 |
| --- | --- | --- |
| 이메일 | ID 토큰의 이메일·검증 상태 제공 | 서버 검증 후 채우기 |
| 이름·프로필 사진 | profile 범위에서 제공 가능, 누락 가능 | 받은 값만 채우고 이름 수정 허용 |
| 휴대전화 | 기본 로그인 정보에 포함되지 않음 | 기존 SMS 입력·인증 유지 |
| 성별 | 기본 로그인 정보에 포함되지 않음 | 필요한 경우 직접 선택 |
| 학번·재학 여부 | 일반 로그인으로 확인 불가 | 학번 입력과 별도 운영 정책 유지 |

이름·사진은 항상 반환되는 값이 아니다. 전화번호·성별은 People API의 별도 데이터 범위가
필요하고 계정에 값이 없을 수도 있다. 이를 받으려고 동의를 늘리는 것보다 기본 로그인
범위만 요청하고 부족한 항목을 짧게 받는 편을 추천한다.
근거: [Google OpenID Connect](https://developers.google.com/identity/openid-connect/openid-connect),
[People API](https://developers.google.com/people/api/rest/v1/people/get).

## 학교 도메인 제한

학교별 이메일 도메인 외에 검증된 Workspace hosted-domain 목록을 관리해야 한다.
계정 선택 화면의 `hd` 힌트는 편의 기능이며 접근 제어가 아니다. 서버에서 서명, 발급자,
대상 client ID, 만료, 요청에 묶인 nonce와 재사용을 확인하고 토큰의 `hd`와 선택 학교의
허용 목록을 비교한다. 이메일 접미사만으로 학교 계정이라고 판단하지 않는다.
Workspace를 사용하지 않거나 `hd`가 없는 계정은 기존 학교 메일 인증으로 안내한다.
동일 학교의 별칭·보조 도메인은 실제 관리형 도메인 관계를 검토한 뒤 등록한다.
근거: [Google ID 토큰 검증](https://developers.google.com/identity/gsi/web/guides/verify-google-id-token).

기존 카카오 계정과 Google 계정은 이메일이 같다는 이유만으로 합치지 않는다. 로그인된
기존 계정에 새 제공자 소유 확인을 거쳐 명시적으로 연결한다. 이미 연결된 제공자 계정의
충돌, 연결 해제 후 로그인 수단 유무, 재로그인/재인증과 감사 기록도 함께 설계해야 한다.
외부 계정의 고유 `sub`를 식별자로 사용하고 이메일 변경과 구분한다.

학교 관리자가 제3자 앱을 차단할 수 있으므로 이메일 인증 대체 경로가 필요하다.
근거: [Google Workspace 앱 접근 제어](https://knowledge.workspace.google.com/admin/apps/control-which-third-party-and-internal-apps-access-google-workspace-data).

## 타 서비스에서 가져온 원칙

Notion은 조직의 허용 이메일 도메인으로 가입을 쉽게 하면서 소유자·관리자·일반 회원·게스트의
역할을 구분한다. BoardBuddy에도 **학교 계정 확인은 간단하게, 크루 권한 부여는 별도로**
적용하는 것이 적합하다. 이번 마이페이지에는 이름 옆 역할 태그를 넣어 현재 권한을 쉽게
확인하도록 했다. 자동 크루 가입은 별도의 크루 설정으로 다뤄야 한다.
근거: [Notion 멤버·관리자·게스트 관리](https://www.notion.com/help/add-members-admins-guests-and-groups).

## 실제 연결에 필요한 다음 작업

- Google Cloud 앱·동의 화면·허용 웹 origin/client ID 구성과 학교별 도메인 검토.
- 백엔드 제공자 연결 모델과 위 검증·명시적 계정 연결 API, 프론트 Google 가입/연결 화면.
- 잘못된 학교, 개인 Gmail, 누락 프로필, 학교 정책 차단, 취소, 계정 충돌, 토큰 재사용 테스트.
- 우선 한두 학교에서 실제 기기로 가입·연결을 검증한 후 지원 학교 확대.

환경 설정과 학교별 계정 체계를 확인하기 전에는 작동하지 않는 Google 버튼을 노출하지 않는다.

## 사업자등록 전 카카오 자동 입력의 범위

사업자등록번호가 없어도 앱 소유자 본인인증과 비즈니스 약관 동의를 거쳐 개인 개발자 비즈
앱으로 전환할 수 있다. 그러나 이름·성별·전화번호는 추가 동의항목 권한이 필요하고,
카카오 공식 FAQ는 그 권한 신청을 사업자 정보가 등록된 비즈 앱으로 제한한다.
현재는 닉네임·사진 등 허용된 항목만 활용하고 실명·성별·전화번호 입력/인증을 유지한다.
닉네임을 실명으로 간주하거나 테스트 앱 권한을 일반 부원 서비스에 사용하는 방식은 피한다.
사업자등록 후에는 가입·탈퇴 화면과 개인정보 처리방침을 준비해 필요한 항목만 심사받고
승인된 범위에서 자동 입력을 확대한다. 이번 코드의 수신·자동 입력 경로는 그때 재사용한다.

근거: [개인 개발자 비즈 앱](https://developers.kakao.com/docs/ko/app-setting/app),
[학생·사업자 정보 없는 개발자 FAQ](https://developers.kakao.com/docs/ko/kakaologin/faq),
[항목별 권한](https://developers.kakao.com/docs/ko/kakaologin/utilize).
